# 청년이봄 운영 UI 가이드

## 목적

청년이봄프로그램은 홍보용 사이트가 아니라 현장 운영 도구다. UI는 예쁜 장식보다 빠른 확인, 낮은 실수율, 반복 업무의 편안함을 우선한다.

적용 대상:

- 방문자 QR 체크인 웹: `index.html`, `css/style.css`, `js/main.js`
- 관리자 웹: `admin.html`, `css/admin.css`, `js/admin.js`
- 직원 운영 프로그램: `staff-dashboard`

## 공통 원칙

- 한 화면에서는 현재 사용자가 해야 할 다음 행동을 가장 먼저 보이게 한다.
- 현장 이용자는 모바일 사용이 대부분이므로 방문자 웹은 모바일 기준으로 먼저 설계한다.
- 직원/관리자 화면은 반복 확인과 처리 속도가 중요하므로 표, 필터, 상태, 버튼을 촘촘하고 조용하게 배치한다.
- 장식용 애니메이션, 3D, 스크롤 연출은 사용하지 않는다.
- 상태 메시지는 짧고 구체적으로 쓴다.
- 색상은 의미를 가져야 하며, 같은 의미에는 같은 색을 쓴다.

## 색상 역할

현재 브랜드/운영 색상은 아래 역할로 사용한다.

- 핑크 `#e93f6f`: 주요 행동, 경고성 주목, 반려/오류 계열
- 그린 `#4a9c44`: 승인, 성공, 이용 가능, 네이버/운영 정상
- 블루 `#376c8e`: 진행 중, 정보성 행동, 수동 일지
- 오렌지 `#c47025`: 대기, 주의, 다운로드/보조 작업
- 잉크 `#34302e`: 기본 텍스트
- 뮤트 `#696461`: 보조 텍스트
- 배경 `#f7f7f6`: 운영 화면 기본 배경
- 선/구분 `#e8e6e4`: 표, 카드, 구분선

색상은 화면을 꾸미는 용도가 아니라 상태를 빨리 구분하기 위한 용도로 사용한다.

## 버튼 규칙

주요 버튼:

- 방문 확인
- 일지 제출
- 예약 신청
- 승인
- 전체 새로고침

보조 버튼:

- 다른 날짜 예약
- 메인으로 돌아가기
- 관리자 페이지
- 시트 열기
- 설정

위험/되돌리기 어려운 버튼:

- 반려
- 취소
- 노쇼

규칙:

- 한 화면에서 가장 중요한 버튼은 1개만 강하게 보이게 한다.
- 직원 프로그램 상단에는 자주 쓰는 버튼만 둔다.
- 자주 쓰지 않는 기능은 `더보기`나 설정 안으로 이동한다.
- 버튼 문구는 동사형으로 쓴다. 예: `전체 새로고침`, `일지 제출`, `승인`, `반려`

## 예약 상태 표준

예약 상태는 웹/네이버 출처를 구분하지 않고 아래 운영 상태로 통일한다.

- `승인 대기`: 예약 신청은 접수됐지만 승인/확정 전
- `승인 완료`: 이용 예정이며 아직 이용일지는 제출되지 않음
- `이용중`: 실제 일지가 제출됐고 현재 시간이 예약 시간 안에 있음
- `이용완료`: 실제 일지가 제출됐고 예약 시간이 지남
- `노쇼`: 일지 미제출 상태에서 예약 시작 10분 경과
- `취소`: 취소 또는 반려된 건

예약 중복 기준:

- 대표자
- 날짜
- 시작 시간
- 종료 시간

위 4개가 같으면 네이버 예약, 웹 예약, 이용일지 기록이 서로 다른 출처여도 같은 건으로 표시한다.

## 예약 표 규칙

직원 운영 프로그램의 예약 표 컬럼은 아래 순서를 기본으로 한다.

1. 시간
2. 대표자
3. 장소
4. 인원수
5. 상태

표시 규칙:

- 출처가 아니라 운영 상태를 먼저 보여준다.
- 네이버/웹 구분은 필요할 때만 상세 또는 보조 정보로 둔다.
- 시간은 `HH:mm~HH:mm` 형식으로 표시한다.
- 인원수는 `3명`처럼 단위를 붙인다.
- 상태 색상은 통일한다.

상태 색상:

- 승인 대기: 오렌지
- 승인 완료: 기본 텍스트
- 이용중: 블루 또는 굵게
- 이용완료: 그린
- 노쇼: 회색 또는 경고색
- 취소: 회색

## 직원 프로그램 구조

메인 화면:

- 오늘 예약·이용을 가장 크게 표시한다.
- 달력은 해당 월 1개만 표시한다.
- 예약 표는 창 크기에 따라 가변적으로 늘어난다.
- 표의 열 너비는 사용자가 조절할 수 있게 한다.

상단 주요 버튼:

- 수동 일지
- 네이버 스마트플레이스
- 전체 새로고침
- 더보기

더보기 메뉴:

- 알림 이력
- 실적 다운로드
- 관리자 페이지
- 시트 열기
- 설정

알림 이력:

- 메인 화면에 항상 노출하지 않는다.
- 로그 확인이 필요할 때만 새 창으로 연다.
- 필터는 `전체`, `방문`, `커넥트룸`, `커리어존`, `이용 제한`을 유지한다.

## 방문자 웹 구조

모바일을 우선한다.

첫 화면:

- 전화번호 뒷자리 입력
- 방문 확인

로그인 후:

- 이름과 기본 정보
- 오늘 예약 일정
- 빠른 이동 버튼
  - 공간 예약
  - 프린터 이용

공간 예약:

- 오늘 날짜를 기본으로 보여준다.
- 다른 날짜 예약을 눌렀을 때 달력을 연다.
- 예약 시간은 그리드로 보여준다.
- 이미 예약된 시간은 비활성화한다.
- 시작/끝 2번 클릭으로 시간 범위를 정한다.

일지 제출:

- 예약 당일만 가능하다.
- 이용 시작 20분 전부터 가능하다.
- 이용자가 알아볼 수 있게 “이용 시작 20분 전부터 일지를 제출할 수 있습니다.”처럼 안내한다.

## 관리자 웹 구조

관리자 화면은 운영형 테이블 중심으로 유지한다.

우선순위:

1. 예약 신청 관리
2. 수동 일지 제출
3. 회원 조회
4. 최근 처리 내역

규칙:

- 승인/반려 버튼은 행 안에서 바로 처리할 수 있게 한다.
- 테이블은 날짜, 시간, 공간, 신청자, 인원, 상태가 빠르게 보이게 한다.
- 장식 카드보다 정보 밀도를 우선한다.

## 문구 규칙

좋은 문구:

- `예약 신청이 접수되었습니다.`
- `이용 시작 20분 전부터 일지를 제출할 수 있습니다.`
- `오늘 방문이 기록되었습니다.`
- `예약 가능한 시간을 선택해 주세요.`

피할 문구:

- 개발자 용어
- 너무 긴 설명
- “오류가 발생했습니다”만 있는 메시지
- 사용자가 다음 행동을 알 수 없는 문구

오류 메시지는 가능한 한 다음 행동을 포함한다.

예:

- `예약 날짜를 확인해 주세요.`
- `이미 예약된 시간입니다. 다른 시간을 선택해 주세요.`
- `오늘 방문 확인을 먼저 진행해 주세요.`

## 보류 항목

현재 프로젝트에는 아래 요소를 적용하지 않는다.

- GSAP/스크롤 애니메이션
- Three.js/WebGL
- Awwwards 스타일 고급 시각 연출
- 마케팅 랜딩페이지 구성
- 가격표/프라이싱 페이지 패턴

이 항목들은 별도 홍보 페이지를 만들 때 다시 검토한다.
