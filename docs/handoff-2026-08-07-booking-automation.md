# Booking Automation Handoff

작성일: 2026-08-07

## 현재 목표

직원관리 프로그램에서 예약 관련 CSV 수동 반영 대신, 네이버 예약 관리자 화면을 기준으로 자동 동기화 흐름을 설계하고 구현 준비를 진행한다.

## 결정된 방향

1. 기준 화면은 `예약현황`이 아니라 `예약자관리`를 사용한다.
2. 이유는 `예약자관리`가 목록형 구조라서 `예약번호` 기준 수집과 중복 제거가 더 쉽기 때문이다.
3. 직원관리 프로그램 요구사항은 아래 두 가지다.
   - 프로그램 시작 시 자동 동기화
   - 사용자가 `새로고침`을 누르면 수동 동기화
4. 수집은 프로그램 UI 안에서 직접 브라우저를 돌리는 대신, 별도 수집 로직에서 처리하는 구조가 더 적합하다.

## 네이버 예약 화면에서 확인한 내용

### 예약현황

- URL: `https://partner.booking.naver.com/bizes/1002115/booking-calendar-view`
- 캘린더형 그리드 구조
- 상태 필터: `전체`, `신청`, `확정`, `예약가능`, `예약불가`, `완료/노쇼`, `잔여예약`
- 화면상 확인용으로는 유용하지만, 주 수집원으로는 유지보수성이 떨어진다.

### 예약자관리

- URL: `https://partner.booking.naver.com/bizes/1002115/booking-list-view`
- 목록형 구조
- 빠른 필터:
  - `오늘이용`
  - `확정대기`
  - `오늘취소`
- 추가 필터:
  - `예약상태`
  - `상품`
  - `쿠폰`
- 각 항목은 상세 링크 `booking-list-view/bookings/{예약번호}` 패턴을 가진다.

## 상품 필터 기준

자동화 대상 상품은 아래 3개로 확정했다.

- `AI 커리어존 (청취Room1)`
- `AI 커리어존 (청취Room2)`
- `청년 커넥트룸`

사이트 동작상 `상품` 필터를 먼저 걸고, 이후 `오늘이용`, `확정대기`, `오늘취소`를 눌러도 상품 필터가 유지되는 방식으로 확인했다.

따라서 수집 순서는 아래로 정리했다.

1. `예약자관리` 진입
2. `상품` 필터 열기
3. `전체` 해제
4. 위 3개 상품만 선택
5. `오늘이용` 수집
6. `확정대기` 수집
7. `오늘취소` 수집

## 구현 메모

- 공통 식별자는 `예약번호`
- 필터별 결과는 `filterType`으로 구분
  - `today_use`
  - `pending_confirm`
  - `today_cancel`
- 출력 파일은 JSON 기준으로 저장
- Playwright는 로그인 세션 유지용 persistent profile 전략 사용

## 현재 저장소에 추가한 파일

- `automation/naver-booking-sync.js`
- `automation/README.md`

## 다음 작업 추천 순서

1. 다른 PC에서 저장소 pull
2. `automation/README.md` 기준으로 로그인 세션 생성
3. 스크립트 실행 후 `outputs/naver-booking-sync.json` 생성 확인
4. 결과 JSON을 직원관리 프로그램과 연결
5. 프로그램 시작 자동 동기화, 수동 새로고침 연동

## 주의사항

- 현재 스크립트는 초기 수집 골격이다.
- 네이버 예약 화면 구조가 바뀌면 선택자 조정이 필요할 수 있다.
- 실제 배포 전에는 `오늘이용`, `확정대기`, `오늘취소` 각각의 결과 건수가 화면 배지 숫자와 맞는지 검증해야 한다.
